Section 06: Methods & Parameters

Detailed architectural breakdown integrating comprehensive explanations, syntax reference matrices, compiler internals, and production C# code.

1. Anatomy of Methods & Execution Flow

If fields define the state of an object, methods define its behavior. A method is a self-contained block of statements that performs an operation and optionally returns a result to the caller.

🔵 Core Concept (from Notes)

In procedural programming, functions existed in global space. In OOP, instance methods are inextricably bound to their parent class. An instance method has direct access to the private state of the instance it is called upon via the hidden this pointer.

2. Parameter Modifiers: val, ref, out, in

By default, C# passes arguments by value (a copy is created). C# provides three explicit modifiers to pass memory references directly:

ModifierCaller Must Initialize?Callee Must Assign?DirectionPrimary Purpose & Memory Behavior
Default (Value)YesNoIn OnlyPasses a copy of the value (for structs) or a copy of the pointer address (for classes). Callee mutations to the variable itself do not affect caller.
refYesNoIn & Out (Bi-directional)Passes the exact memory address of the caller variable. Callee modifications mutate caller variable directly.
outNoYes (Strictly enforced by compiler)Out OnlyUsed to return multiple values from a method. Callee must assign a valid value before exiting.
inYesNo (ReadOnly: callee cannot mutate)In Only (By Reference)Passes large value types (structs) by reference to prevent copying overhead while strictly guaranteeing immutability.
Parameter Modifiers in Action 
public class ParameterMechanics
{
    // 1. Pass by value: caller variable unchanged
    public void ByValue(int x) { x += 10; }

    // 2. Pass by ref: caller variable mutated
    public void ByRef(ref int x) { x += 10; }

    // 3. Pass by out: callee must assign
    public bool TryDivide(int numerator, int denominator, out int result)
    {
        if (denominator == 0)
        {
            result = 0; // Required to assign even on failure!
            return false;
        }
        result = numerator / denominator;
        return true;
    }

    // 4. Pass by in: zero-copy read-only
    public void PrintLargeMatrix(in Matrix4x4 matrix)
    {
        // matrix.M11 = 5.0f; // CS1604: Cannot assign to variable 'matrix' because it is read-only
        Console.WriteLine($"Matrix element: {matrix.M11}");
    }
}

3. Variable-Length Arguments (params)

The params keyword allows a method to accept any arbitrary number of arguments of the specified type without requiring the caller to manually instantiate an array:

params Array Usage 
public class MathUtility
{
    // params must be the final parameter in the signature
    public static int Sum(params int[] numbers)
    {
        int total = 0;
        foreach (int n in numbers) total += n;
        return total;
    }
}

// Caller can supply comma-separated values, an array, or zero arguments:
int s1 = MathUtility.Sum(1, 2, 3, 4, 5);      // Returns 15
int s2 = MathUtility.Sum(10, 20);            // Returns 30
int s3 = MathUtility.Sum();                  // Returns 0
int s4 = MathUtility.Sum(new int[] { 8, 9 }); // Returns 17

4. Method Overloading & Signature Resolution

Method Overloading allows multiple methods in the same class to share the same name, provided their parameter signatures are distinct. A method signature consists of:

  • The method name.
  • The number, type, and modifiers of its parameters.
🟣 Under the Hood / Compiler Lowering

The return type is strictly NOT part of a method's signature. Two methods differing only by return type (e.g., int Calculate() vs double Calculate()) cause compiler error CS0111.

5. Expression-Bodied Methods

For concise methods whose body consists of a single expression, C# supports the expression-bodied lambda syntax (=>):

Expression-Bodied Method 
// Traditional multi-line method
public double Square(double x)
{
    return x * x;
}

// Equivalent modern expression-bodied method
public double SquareConcise(double x) => x * x;

6. Local Functions & Scope Optimization

C# allows defining methods inside other methods. These local functions are scoped strictly to the enclosing block, preventing API pollution and optimizing memory allocations:

Local Function with Argument Validation 
public static IEnumerable<int> GenerateEvenNumbers(int count)
{
    if (count < 0) throw new ArgumentOutOfRangeException(nameof(count));

    // Local function: separates eager validation from deferred execution
    return CoreIterator();

    IEnumerable<int> CoreIterator()
    {
        for (int i = 0; i < count; i++)
        {
            yield return i * 2;
        }
    }
}

7. Common Parameter Gotchas

🟠 Compiler Trap & Common Gotcha

Trap: Calling a method with params int[] inside a loop that runs millions of times.

Under the Hood: In C# versions prior to C# 13, passing comma-separated values causes the compiler to generate a heap array allocation (new int[3]) on every single call, creating enormous GC pressure.

Optimization: In hot paths, supply explicit single/two-argument overload methods or leverage modern C# 13 params ReadOnlySpan<T> to eliminate heap allocations completely.
