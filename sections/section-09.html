Section 09: Properties & Indexers

Detailed architectural breakdown integrating comprehensive explanations, syntax reference matrices, compiler internals, and production C# code.

1. Why Properties: Encapsulation Without Getter Boilerplate

In classical languages like Java or C++, protecting a private field requires authoring tedious pairs of getter and setter methods (getName() and setName(string val)). C# properties elevate this pattern into a first-class language primitive:

🔵 Core Concept (from Notes)

To the external consumer, a property looks and behaves cleanly like a public field (product.Price = 49.99m;). But under the hood, reading or writing to the property actually executes special compiler-generated accessor methods: get and set.

This provides the simplicity and beauty of field syntax with the rigorous encapsulation, data validation, and lazy evaluation capabilities of methods.

2. Auto-Implemented Properties & Backing Fields

When no custom validation or transformation is required, C# provides Auto-Implemented Properties:

Auto-Implemented Properties 
public class Customer
{
    // Auto-implemented property with inline default initializer
    public string Name { get; set; } = "Anonymous";
    
    // Read-only auto-property (can only be set in constructor)
    public int CustomerId { get; }

    public Customer(int id, string name)
    {
        CustomerId = id;
        Name = name;
    }
}
🟣 Under the Hood / Compiler Lowering

When Roslyn compiles public string Name { get; set; }, it automatically synthesizes a private backing field with an unspeakable name, along with get and set methods: 

// Under the hood generated by Roslyn:
[CompilerGenerated]
private string <Name>k__BackingField;

public string get_Name()
{
    return this.<Name>k__BackingField;
}

public void set_Name(string value)
{
    this.<Name>k__BackingField = value;
}

3. Full Properties with Validation Logic

When an application needs to enforce business invariants (such as preventing negative balances or validating email formatting), use a Full Property with an explicit private backing field:

Full Property with Validation 
public class BankAccount
{
    private decimal _balance; // Explicit private backing field

    public decimal Balance
    {
        get => _balance;
        set
        {
            if (value < 0)
            {
                throw new ArgumentOutOfRangeException(nameof(value), "Balance cannot be negative.");
            }
            _balance = value;
        }
    }
}

4. Modern init-Only Accessors & Immutability

Introduced in C# 9, init accessors provide immutable data structures while retaining the elegance of C# object initializers:

init-Only Accessor Demonstration 
public class UserProfile
{
    public int Id { get; init; }
    public string Email { get; init; }
    public string Role { get; set; } // Mutable
}

// Caller can initialize using clean object initializer syntax:
var user = new UserProfile
{
    Id = 101,
    Email = "admin@enterprise.com",
    Role = "SuperUser"
};

// Valid: Role has a standard setter
user.Role = "StandardUser";

// ILLEGAL: Triggers compile error CS8852!
// user.Id = 202; // Init-only property can only be assigned in an object initializer or constructor!

5. Expression-Bodied & Read-Only Computed Properties

Properties can calculate values dynamically on the fly without occupying any storage field:

Computed Expression-Bodied Properties 
public class Person
{
    public string FirstName { get; set; }
    public string LastName { get; set; }

    // Read-only computed property evaluated dynamically on every read
    public string FullName => $"{FirstName} {LastName}".Trim();

    // Expression-bodied property with explicit get
    public bool IsNameEmpty => string.IsNullOrEmpty(FullName);
}

6. Indexers: Array-Like Syntax for Objects

An Indexer allows instances of your class to be indexed just like arrays using square bracket notation obj[index]. They are declared using the this[...] keyword:

Custom Generic Indexer 
public class SampleCollection<T>
{
    private readonly T[] _elements = new T[100];

    // Integer-based Indexer
    public T this[int index]
    {
        get
        {
            if (index < 0 || index >= _elements.Length)
                throw new IndexOutOfRangeException();
            return _elements[index];
        }
        set
        {
            if (index < 0 || index >= _elements.Length)
                throw new IndexOutOfRangeException();
            _elements[index] = value;
        }
    }
}

// Caller usage:
var list = new SampleCollection<string>();
list[0] = "First Entry";
list[1] = "Second Entry";
Console.WriteLine(list[0]); // Prints: "First Entry"

7. Common Property Traps

🟠 Compiler Trap & Common Gotcha

Devastating Bug: Referencing the property name inside its own setter: 

public int Age
{
    get => _age;
    set => Age = value; // BUG! Calls set_Age recursively until StackOverflowException!
}

Fix: Always assign to the private backing field _age = value; inside the setter!
