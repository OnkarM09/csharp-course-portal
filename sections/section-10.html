Section 10: Inheritance, Hiding & Overriding

Detailed architectural breakdown integrating comprehensive explanations, syntax reference matrices, compiler internals, and production C# code.

1. "is-a" Relationship & Base/Derived Classes

Inheritance is a core pillar of OOP that models a hierarchical "is-a" relationship between types. A derived child class acquires all non-private fields, properties, and methods of an existing base parent class:

🔵 Core Concept (from Notes)

Instead of duplicating shared logic across multiple similar types (e.g. Manager, Developer, SalesPerson all needing Id, Name, and Salary), we place common state and operations in a shared Employee base class.

2. Constructor Execution Order & base() Chaining

When a derived class object is created, the base class constructor ALWAYS executes first to ensure foundational state is established before derived constructor logic runs:

Base Constructor Chaining 
public class Person
{
    public string Name { get; }
    public int Age { get; }

    public Person(string name, int age)
    {
        Name = name;
        Age = age;
        Console.WriteLine("1. Person Base Constructor Executed");
    }
}

public class Employee : Person
{
    public string Department { get; }

    // Explicitly chains to Person constructor via base(...)
    public Employee(string name, int age, string department) 
        : base(name, age)
    {
        Department = department;
        Console.WriteLine("2. Employee Derived Constructor Executed");
    }
}

3. Polymorphism: virtual, override & vtable

Polymorphism allows a base class reference variable to execute derived class behaviors dynamically at runtime. For dynamic dispatch to occur:

  • The base class method must be marked virtual.
  • The derived class method must be marked override.
🟣 Under the Hood / Compiler Lowering

Every class with virtual methods contains a MethodTable (vtable) pointer in its 8-byte object header on the heap. When calling employee.CalculateBonus(), the CLR does not jump to a hardcoded code address. Instead, it inspects the object's runtime MethodTable and invokes the specific overridden function pointer.

4. Method Hiding with the new Keyword

If a derived class introduces a method with the same signature as a base method without using override, it hides (or shadows) the base method. Use the new keyword to suppress compiler warnings:

Invocation Scenario<code>virtual / override</code> (Overriding)<code>new</code> Keyword (Method Hiding)
Base reference to derived object: Base b = new Derived(); b.DoWork();Executes Derived.DoWork() (Dynamic Dispatch via vtable)Executes Base.DoWork() (Static Early Binding via reference type)
Derived reference: Derived d = new Derived(); d.DoWork();Executes Derived.DoWork()Executes Derived.DoWork()
Architectural IntentExtending or specializing base polymorphic contractCompletely severing inheritance linkage for that specific method

5. Sealing Classes & Preventing Overrides

The sealed keyword blocks downstream inheritance:

Sealed Class & Method 
// Cannot be inherited by any other class
public sealed class SecurityTokenProvider
{
    public string GenerateToken() => Guid.NewGuid().ToString("N");
}

public class BaseRenderer
{
    public virtual void Render() { /* ... */ }
}

public class SpecializedRenderer : BaseRenderer
{
    // Seals this method: sub-classes of SpecializedRenderer cannot override Render()
    public sealed override void Render() { /* ... */ }
}

6. Overriding vs Hiding Pitfalls

🟠 Compiler Trap & Common Gotcha

Bug: Writing public new void CalculatePay() when intending to specialize behavior for collections of Employee.

Failure: When looping through List<Employee>, the base method runs for every manager, ignoring the specialized manager pay algorithm! Always use override for true polymorphic behavior.
