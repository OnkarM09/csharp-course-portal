Section 14: Structures (Structs) & Value Semantics

Detailed architectural breakdown integrating comprehensive explanations, syntax reference matrices, compiler internals, and production C# code.

1. Structs vs Classes: Value vs Reference Semantics

A struct (structure) is a composite data type that has value semantics. While classes are allocated on the managed heap and accessed via reference pointers, structs are allocated inline wherever they are declared (directly on the stack for local variables, or embedded inside the heap object if declared as a class field).

DimensionClass (Reference Type)Struct (Value Type)
Memory LocationAlways on the Managed HeapInline (Stack for locals; inside parent object if field)
Assignment BehaviorCopies the reference pointer (both variables point to same instance)Copies all fields bit-for-bit (independent new clone)
InheritanceSupports inheritance hierarchies from classesCannot inherit from other structs/classes (implements interfaces only)
Garbage CollectionRequires GC to allocate and reclaimZero GC overhead; popped instantly when stack frame exits
Default ValuenullAll fields zeroed (0, false, null)

3. Copy-on-Assignment & Mutation Behavior

Copy-by-Value Behavior 
public struct GeoPoint
{
    public double Latitude;
    public double Longitude;

    public GeoPoint(double lat, double lon) { Latitude = lat; Longitude = lon; }
}

GeoPoint p1 = new GeoPoint(40.7128, -74.0060);
GeoPoint p2 = p1; // COMPLETE COPY OF MEMORY BITS!

p2.Latitude = 51.5074; // Mutating p2 has ZERO effect on p1!

Console.WriteLine(p1.Latitude); // Still 40.7128!

4. readonly struct & Defensive Copy Prevention

When a mutable struct is passed as an in parameter or marked readonly, the compiler creates hidden defensive copies on every member access to prevent mutation. Marking the struct readonly struct tells Roslyn all fields are immutable, completely eliminating defensive copy overhead:

readonly struct 
public readonly struct Vector3D
{
    public double X { get; }
    public double Y { get; }
    public double Z { get; }

    public Vector3D(double x, double y, double z) => (X, Y, Z) = (x, y, z);

    public double MagnitudeSq => (X * X) + (Y * Y) + (Z * Z);
}

5. ref struct & Span<T> Stack-Only Guarantees

A ref struct is strictly enforced by the compiler to reside only on the execution stack. It can never be boxed, cannot be stored in a class field, cannot be used in async state machines, and cannot be captured in lambdas. This guarantees high-speed zero-allocation operations like Span<T> and ReadOnlySpan<T>:

ref struct 
public ref struct StackBuffer
{
    public Span<byte> Buffer;
    public int Length;
}

6. Struct Gotchas & Boxing Overhead

🟠 Compiler Trap & Common Gotcha

Trap: Casting a struct to an interface or object: 

GeoPoint p = new GeoPoint(1, 2);
object boxed = p; // BOXING! Allocates a new object on the Heap!

Consequence: Destroys the zero-allocation performance benefit of structs and generates GC garbage.
