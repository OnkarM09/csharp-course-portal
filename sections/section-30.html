Section 30: C# 9 & C# 10 Features (.NET 5 & 6)

Detailed architectural breakdown integrating comprehensive explanations, syntax reference matrices, compiler internals, and production C# code.

1. Records Revolution: Value Equality & Immutability

Introduced in C# 9, Records (record class and C# 10 record struct) are designed specifically for immutable data-centric models. Unlike standard classes which use reference equality, records provide automatic value-based equality:

🔵 Core Concept (from Notes)

In a single, elegant line of source code: 

public record Person(string FirstName, string LastName);

The Roslyn compiler synthesizes:

  1. Init-only public properties for FirstName and LastName.
  2. A primary constructor that initializes both properties.
  3. A custom Deconstruct method for tuple unpacking.
  4. A copy constructor used by the with expression.
  5. Complete overrides for Equals(object), Equals(Person), GetHashCode(), and == / != operators.
  6. A custom ToString() method displaying formatted property values!
Record Value Equality 
public record Customer(int Id, string Name, string Email);

var c1 = new Customer(101, "Alice", "alice@enterprise.com");
var c2 = new Customer(101, "Alice", "alice@enterprise.com");

// Value-based equality evaluates to TRUE!
Console.WriteLine(c1 == c2);      // True!
Console.WriteLine(c1.Equals(c2)); // True!
Console.WriteLine(c1);            // Output: Customer { Id = 101, Name = Alice, Email = alice@enterprise.com }

2. Non-Destructive Mutation with the with Expression

Immutability is powerful, but modifying a single field in an immutable object traditionally required tedious constructor calls. The with expression creates a new record instance with specified properties modified while preserving all other original fields:

Non-Destructive Mutation 
var originalOrder = new OrderRecord(4001, "Customer-A", 150.00m, "Processing");

// Non-destructive mutation: produces an independent clone with Status updated
var updatedOrder = originalOrder with { Status = "Shipped" };

Console.WriteLine($"Original: {originalOrder.Status}"); // Processing
Console.WriteLine($"Updated:  {updatedOrder.Status}");  // Shipped

3. Target-Typed new & Target-Typed Conditionals

When the type of an object is already known from the declaration, you can omit the redundant type name in new:

Target-Typed new 
// Target-typed new expressions
Dictionary<string, List<int>> map = new(); // Replaces new Dictionary<string, List<int>>()
Person worker = new("Sarah", "Connor");

// Target-typed conditional expression
int? score = condition ? 100 : null; // In C# 8 this failed; in C# 9+ compiler infers int?

4. Relational & Logical Pattern Matching (and, or, not)

Pattern Matching Combinators 
public static bool IsValidHttpPort(int port) => port switch
{
    80 or 443 or (>= 8000 and <= 8088) => true,
    _ => false
};

// 'not' pattern eliminates null checks
if (customer is not null)
{
    Console.WriteLine(customer.Name);
}

5. C# 10 Features: Global Usings & Extended Patterns

C# 10 introduced record structs (value-type records on the stack), extended property patterns, and constant interpolated strings:

Extended Property Pattern 
// Extended nested property patterns (C# 10)
// Old C# 9: { Address: { City: "Seattle" } }
// Clean C# 10:
if (employee is { Address.City: "Seattle", Department.Manager.IsActive: true })
{
    Console.WriteLine("Active Seattle employee.");
}

6. Record Traps & Reference vs Value Semantics

🟠 Compiler Trap & Common Gotcha

Trap: If a record contains a mutable collection (e.g. List<string>), the with expression performs a shallow copy of the pointer!

Both the original record and the cloned record point to the exact same list on the heap. Mutating the list in one record mutates it in both!

Fix: Use immutable collections like ImmutableList<T> or IReadOnlyList<T> in record properties.
