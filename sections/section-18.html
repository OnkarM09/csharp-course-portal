Section 18: Extension Methods & Pattern Matching

Detailed architectural breakdown integrating comprehensive explanations, syntax reference matrices, compiler internals, and production C# code.

1. What Are Extension Methods & Syntactic Sugar

Extension methods allow you to inject new methods into existing types (including BCL classes like string, DateTime, or interfaces like IEnumerable<T>) without creating a derived subclass or modifying the original compiled library:

🔵 Core Concept (from Notes)

To the developer writing code with IntelliSense, an extension method looks and feels like a regular instance method called directly on the object ("my text".ToSlug()).

Under the hood, however, it is pure compiler syntactic sugar: the Roslyn compiler lowers the call into a standard static method invocation: StringExtensions.ToSlug("my text").

2. Authoring Extension Methods (static class & this)

To declare an extension method, follow these three rules:

  1. The containing class must be static.
  2. The method itself must be static.
  3. The first parameter must be prefixed with the this modifier, denoting the target type being extended.
Authoring & Invoking Extension Methods 
namespace Enterprise.Extensions;

public static class StringUtilitiesExtensions
{
    // Extends System.String
    public static string ToSlug(this string input)
    {
        if (string.IsNullOrWhiteSpace(input)) return string.Empty;
        return input.ToLowerInvariant().Replace(" ", "-");
    }

    // Extends System.DateTime
    public static bool IsWeekend(this DateTime date) =>
        date.DayOfWeek == DayOfWeek.Saturday || date.DayOfWeek == DayOfWeek.Sunday;
}

// Caller usage:
using Enterprise.Extensions;

string title = "C Sharp Architecture Masterclass";
Console.WriteLine(title.ToSlug()); // "c-sharp-architecture-masterclass"

DateTime now = DateTime.Now;
Console.WriteLine($"Is today weekend? {now.IsWeekend()}");

3. Pattern Matching Evolution in C#

Pattern matching allows you to inspect the shape, type, and values of data structures cleanly:

Type Pattern with Variable Binding 
// 1. Declaration & Type Pattern with 'is'
object data = 150.75m;

if (data is decimal balance && balance > 100m)
{
    Console.WriteLine($"Account has healthy balance: {balance:C}");
}

4. Modern Switch Expressions

The traditional switch statement is imperative and ceremonial. Modern C# provides expression-based pattern matching (switch expressions):

Property Pattern Matching in Switch Expression 
public decimal CalculateDiscount(Customer customer) => customer switch
{
    { IsVip: true, TotalPurchases: > 5000m } => 0.25m,  // 25% VIP High-Spender
    { IsVip: true }                         => 0.15m,  // 15% VIP
    { TotalPurchases: > 1000m }             => 0.05m,  // 5% Regular High-Spender
    null                                    => throw new ArgumentNullException(nameof(customer)),
    _                                       => 0.00m   // Default discard pattern
};

5. Property, Positional & Relational Patterns

Relational and Logical Patterns 
// Relational & Logical Patterns (and, or, not)
public static string CategorizeTemperature(int temp) => temp switch
{
    < 0                  => "Freezing",
    >= 0 and < 15        => "Cold",
    >= 15 and <= 25      => "Comfortable",
    > 25 and not >= 40   => "Warm",
    _                    => "Extreme Heat"
};

6. Extension Method & Pattern Traps

🟠 Compiler Trap & Common Gotcha

Trap: If a class introduces an instance method with the exact same name and signature as your extension method, the compiler silently binds to the instance method! Your extension method will no longer be called, without producing any compile errors.
