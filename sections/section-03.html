2. The .NET CLI Command Matrix

The dotnet CLI is the universal driver for creating, compiling, testing, and packaging .NET applications across all operating systems.

CommandSyntax ExampleDescription & Output
dotnet newdotnet new console -o MyFirstAppCreates a new project from a built-in template (console, webapi, classlib, blazor).
dotnet builddotnet build -c ReleaseCompiles the project and its dependencies into CIL binaries (.dll).
dotnet rundotnet run --project MyFirstAppBuilds (if out of date) and immediately launches the target executable.
dotnet testdotnet test --logger "console;verbosity=detailed"Executes all unit and integration test runners (xUnit, NUnit, MSTest).
dotnet add packagedotnet add package Newtonsoft.JsonResolves and adds a NuGet package dependency to the .csproj file.
dotnet publishdotnet publish -c Release -r win-x64 --self-containedPackages the application and its runtime dependencies for deployment.

3. Anatomy of a .NET Project (.csproj)

Modern SDK-style .csproj files are clean, readable XML configuration files that control compilation, packaging, and dependency resolution.

MyFirstApp.csproj 
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <!-- Target runtime framework: .NET 9.0 -->
    <OutputType>Exe</OutputType>
    <TargetFramework>net9.0</TargetFramework>
    
    <!-- Enable C# Nullable Reference Types checking -->
    <Nullable>enable</Nullable>
    
    <!-- Auto-import common namespaces like System, System.Linq, System.IO -->
    <ImplicitUsings>enable</ImplicitUsings>
    
    <!-- Enforce latest language feature set -->
    <LangVersion>latest</LangVersion>
  </PropertyGroup>

  <!-- External NuGet Package References -->
  <ItemGroup>
    <PackageReference Include="Spectre.Console" Version="0.49.1" />
  </ItemGroup>

</Project>

4. Program.cs & Top-Level Statements Lowering

Since C# 9, console applications no longer require ceremonial boilerplate like namespace MyCompany, class Program, and static void Main(string[] args). You can write your logic directly at the top level:

Program.cs (Top-Level) 
// Modern C# 10+ Top-Level Statements
Console.WriteLine("Hello, Developer!");

if (args.Length > 0)
{
    Console.WriteLine($"Command Line Argument: {args[0]}");
}
🟣 Under the Hood / Compiler Lowering

The Roslyn compiler behind the scenes lowers the top-level script into a standard static class and entry-point method: 

// Under the hood generated by Roslyn:
internal class <Program>$
{
    private static void <Main>$(string[] args)
    {
        Console.WriteLine("Hello, Developer!");
        if (args.Length > 0)
        {
            Console.WriteLine($"Command Line Argument: {args[0]}");
        }
    }
}

Notice that the generated class and method names use characters (like < and $) that are illegal in normal C# source code, preventing any naming collision with user-defined classes.

5. Build, Run, Release & Publish Configurations

When building for production, always specify the Release configuration. In Debug mode, the compiler inserts no-op instructions (nop) and preserves full symbol tables to enable step-by-step debugging. In Release mode, the JIT optimizes aggressively, inlines small methods, eliminates dead code, and strips debug overhead.

📊 Diagram: Debug Build vs Optimized Release Publish
Debug Build:   [Source] ---> Roslyn (No Inlining, PDBs, nop) ---> RyuJIT (Fast startup, step debug)
Release Build: [Source] ---> Roslyn (Optimized IL) ----------> RyuJIT (Aggressive inlining, SIMD, Loop Unroll)

6. Debugging Techniques & Breakpoint Mechanics

Mastering the debugger is the single fastest way to isolate and resolve logic defects in your codebase:

  • Breakpoints (F9): Pauses execution immediately before the targeted line executes.
  • Step Over (F10): Executes the current line of code and advances to the next without drilling into called methods.
  • Step Into (F11): Steps into the internal code of the method being called.
  • Step Out (Shift+F11): Runs the remainder of the current method and pauses in the calling method.
  • Watch & Locals Window: Inspects live variables, memory references, and evaluates runtime C# expressions while execution is suspended.

7. Common Tooling & Build Traps

🟠 Compiler Trap & Common Gotcha

Trap: Creating two .cs files in the same project that both contain top-level statements.

Error: CS8802: Only one compilation unit can have top-level statements.

Fix: Exactly one file in your executable project can contain top-level statements to act as the application entry point. All other files must use explicit class and namespace definitions.
