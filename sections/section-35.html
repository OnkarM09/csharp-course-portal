Section 35: C# 12 New Features (.NET 8)

Detailed architectural breakdown integrating comprehensive explanations, syntax reference matrices, compiler internals, and production C# code.

Features

1. Primary Constructors in Classes

C# 12 extends the concept of primary constructors to classes, a feature previously available only for record types since C# 9. This enhancement provides a more concise and streamlined way to declare constructor parameters directly within the class declaration, promoting immutable data and reducing boilerplate code for common scenarios. Problem Solved: Before C# 12, defining constructor parameters and then assigning them to properties often involved repetition, especially for simple data classes: // Pre-C# 12 class constructor public class OldUser { public string Name { get; } public int Age { get; } public OldUser(string name, int age) { Name = name; Age = age; } } This is boilerplate for simply taking constructor parameters and making them available as properties. While record types addressed this, their value-based equality semantics weren't always desired for classes. Syntax and Behavior in C# 12: With primary constructors, you declare parameters directly after the class name, similar to records: // C# 12 primary constructor for class public class NewUser(string name, int age) { public string Name { get; } = name; // Initialize properties using primary constructor parameters public int Age { get; } = age; } Key Characteristics and Rules:

1. Parameter Scope: Parameters declared in the primary constructor are in

scope throughout the entire class body, including:

  • Property initializers ({ get; } = name;)
  • Method bodies
  • Nested types
  • Other constructors (via this(...) calls)

2. Field/Property Initialization: You can directly initialize properties or fields

using the primary constructor parameters. If a parameter is not used to initialize a field or property, it is only available within the constructor's scope for other logic.

3. No Automatic Property Creation: Unlike record types, primary

constructors in classes do not automatically create public properties for each parameter. You must explicitly define and initialize properties if you want the data to be accessible outside the constructor's immediate scope.

4. Base Class Constructors: You can pass primary constructor parameters

directly to a base class constructor using the base(...) syntax: public class BaseClass(int id) { public int Id { get; } = id; } public class DerivedClass(int id, string name) : BaseClass(id) { public string Name { get; } = name; }

5. Coexistence with Other Constructors:

  • If you define other constructors (secondary constructors) in the class, they must chain to the primary constructor using this(...).
  • If a class has a primary constructor, an implicit parameterless constructor is not generated unless you explicitly define one (and it must chain to this()).

6. Lifetime of Parameters: Primary constructor parameters are effectively

"promoted" to fields if they are captured by instance members (e.g., used to initialize a property or accessed in a method). This ensures their values persist for the lifetime of the object. If a parameter is only used within the constructor itself, it won't necessarily become a field. Real-World Examples: Example 1: Simple Data Class public class TemperatureSensor(string location, double initialReading) { public string Location { get; } = location; public double CurrentReading { get; set; } = initialReading; // Can be mutable public void UpdateReading(double newReading) { CurrentReading = newReading; Console.WriteLine($"Sensor at {Location} updated to {CurrentReading}°C"); } public string GetStatus() { // Primary constructor parameters are in scope here return $"Sensor at '{location}' is active with reading {CurrentReading} °C."; } } // Usage: // var livingRoomSensor = new TemperatureSensor("Living Room", 22.5); // Console.WriteLine(livingRoomSensor.GetStatus()); // livingRoomSensor.UpdateReading(23.1); // Console.WriteLine(livingRoomSensor.GetStatus()); Example 2: Chaining with Secondary Constructors public class Product(int id, string name, decimal price) { public int Id { get; } = id; public string Name { get; } = name; public decimal Price { get; } = price; public DateTime CreatedDate { get; } // Secondary constructor chaining to the primary constructor public Product(int id, string name, decimal price, DateTime createdDate) : this(id, name, price) // Chains to the primary constructor { CreatedDate = createdDate; } // You can add an explicit parameterless constructor, but it MUST chain to the primary public Product() : this(0, "Unknown", 0m) { CreatedDate = DateTime.MinValue; } public void DisplayProduct() { Console.WriteLine($"Product ID: {Id}, Name: {Name}, Price: {Price:C}, Created: {CreatedDate:d}"); } } // Usage: // var laptop = new Product(1, "Laptop", 1200.00m); // laptop.DisplayProduct(); // CreatedDate will be default(DateTime) // var monitor = new Product(2, "Monitor", 300.00m, DateTime.Now.AddDays(-30)); // monitor.DisplayProduct(); // var defaultProduct = new Product(); // defaultProduct.DisplayProduct(); Example 3: Using Primary Constructor Parameters in Methods and Instance Members public class Logger(string sourceName) { private readonly string _logPrefix = $"[{sourceName}] "; // Use parameter in field initializer public void LogInfo(string message) { Console.WriteLine($"{_logPrefix}INFO: {message}"); } public void LogError(string message) { // Parameter 'sourceName' is directly accessible in methods Console.Error.WriteLine($"[{sourceName}] ERROR: {message}"); } } // Usage: // var consoleLogger = new Logger("ConsoleApp"); // consoleLogger.LogInfo("Application started successfully."); // consoleLogger.LogError("Failed to connect to database."); Benefits:

  • Conciseness: Reduces boilerplate code for defining and initializing properties from constructor parameters.
  • Readability: Makes the primary purpose of a class (what data it holds) immediately clear from its declaration.
  • Immutability Support: Encourages the use of init accessors or readonly fields for constructor-initialized data, supporting immutable patterns.
  • Consistency: Aligns class construction syntax with record types, making the language more cohesive. Primary constructors are a valuable addition for writing cleaner, more maintainable, and often more robust class definitions in C# 12.

2. Collection Expressions

C# 12 introduces Collection Expressions, a powerful and concise syntax for creating common collection types. This feature leverages the new spread element (..) to provide a unified way to initialize arrays, Span<T>, and any type that supports the collection initializer pattern (like List<T>, HashSet<T>, etc.). Problem Solved: Before C# 12, creating collections often involved different syntaxes or more verbose approaches depending on the collection type:

C# 
// Pre-C# 12 ways to create collections
int[] array = new int[] { 1, 2, 3 };
List<string> list = new List<string> { "A", "B", "C" };
HashSet<char> set = new HashSet<char> { 'x', 'y', 'z' };
// Concatenating collections was also more verbose
int[] moreNumbers = new int[] { 4, 5, 6 };
int[] combinedArray = array.Concat(moreNumbers).ToArray(); // Requires
LINQ
List<int> combinedList = new List<int>(list) { 4, 5, 6 }; // Or
list.AddRange(new [] {4,5,6});
Collection expressions aim to simplify this, making collection creation more
consistent and readable.
Syntax and Features:
Collection expressions use square brackets [] to enclose the elements, similar to
array initializers, but with enhanced capabilities.
  • Basic Syntax: // Creating an array int[] numbers = [1, 2, 3]; // Creating a List<string> List<string> names = ["Alice", "Bob", "Charlie"]; // Creating a Span<int> (implicitly convertible from an array) Span<int> span = [10, 20, 30];
  • Spread Element (..): The most significant feature is the spread element (..), which allows you to inline elements from another collection into the new collection expression. int[] odds = [1, 3, 5]; int[] evens = [2, 4, 6]; int[] combined = [.. odds, .. evens, 7, 8]; // Result: [1, 3, 5, 2, 4, 6, 7, 8]
  • The spread element must be followed by an expression that evaluates to a collection.
  • It effectively "flattens" the elements of the source collection into the new one.
  • It works with IEnumerable<T>, Span<T>, ReadOnlySpan<T>, and array types.
  • Target-Typed Context: Collection expressions are target-typed. The compiler infers the exact type of the collection from the context.
C# 
IEnumerable<int> iEnumerable = [1, 2, 3]; // Inferred as int[] at
runtime
IReadOnlyList<string> readOnlyList = ["A", "B", "C"]; // Inferred as string[] at
runtime
If the target type is IEnumerable<T>, IReadOnlyList<T>, or a base interface,
the compiler will default to creating an array (T[]). You can explicitly specify a
different type if needed (e.g., new List<int>([1, 2, 3])).
  • Empty Collection: List<int> emptyList = []; // Creates an empty List<int> int[] emptyArray = []; // Creates an empty int[] Real-World Examples: Example 1: Creating and Combining Different Collections using System; using System.Collections.Generic; using System.Linq; // For demonstration of old way public static class CollectionExpressionsDemo { public static void RunExamples() { Console.WriteLine("--- Collection Expressions Demo ---"); // Basic Array int[] scores = [90, 85, 92, 78]; Console.WriteLine($"Scores: [{string.Join(", ", scores)}]"); // Basic List List<string> fruits = ["Apple", "Banana", "Cherry"]; Console.WriteLine($"Fruits: [{string.Join(", ", fruits)}]"); // Combining arrays with spread element int[] topScores = [95, 98]; int[] allScores = [.. scores, .. topScores, 100]; Console.WriteLine($"All Scores: [{string.Join(", ", allScores)}]"); // [90, 85, 92, 78, 95, 98, 100] // Combining lists or arrays into a new List List<string> moreFruits = ["Date", "Elderberry"]; List<string> fullFruitList = [.. fruits, "Grape", .. moreFruits]; Console.WriteLine($"Full Fruit List: [{string.Join(", ", fullFruitList)}]"); // [Apple, Banana, Cherry, Grape, Date, Elderberry] // Creating a Span<char> from literal values Span<char> greeting = ['H', 'e', 'l', 'l', 'o']; Console.WriteLine($"Greeting Span: {new string(greeting)}"); // Creating a HashSet HashSet<int> uniqueNumbers = [1, 2, 3, 2, 4]; // Set will contain {1, 2, 3, 4} Console.WriteLine($"Unique Numbers: [{string.Join(", ", uniqueNumbers)}]"); Console.WriteLine("\n--- Collection Expressions Demo Finished ---"); } } // Call from Main: // public static void Main(string[] args) // { // CollectionExpressionsDemo.RunExamples(); // } Example 2: Usage in Method Parameters and Return Types Collection expressions make method calls more concise when passing collections.
C# 
public class DataProcessor
{
public void ProcessData(IEnumerable<string> data)
{
Console.WriteLine($"\nProcessing data items: {data.Count()}");
foreach (var item in data)
{
Console.WriteLine($"- {item}");
}
}
public int[] MergeArrays(int[] arr1, int[] arr2)
{
return [.. arr1, .. arr2]; // Return a new array by combining inputs
}
public ReadOnlySpan<byte> GetReadOnlyDataPacket()
{
byte header = 0xAA;
byte version = 0x01;
byte[] payload = [0x01, 0x02, 0x03]; // Inline array
return [header, version, .. payload]; // Returns a ReadOnlySpan<byte>
}
}
// Usage:
// var processor = new DataProcessor();
// processor.ProcessData(["Log entry 1", "Log entry 2"]);
// int[] arrayA = [10, 20];
// int[] arrayB = [30, 40];
// int[] merged = processor.MergeArrays(arrayA, arrayB);
// Console.WriteLine($"Merged Array: [{string.Join(", ", merged)}]");
// ReadOnlySpan<byte> packet = processor.GetReadOnlyDataPacket();
// Console.WriteLine($"Data Packet: [{string.Join(", ", packet.ToArray())}]");
Benefits:
  • Conciseness: Significantly reduces the verbosity of creating and initializing collections.
  • Readability: The [] syntax with .. is intuitive and clearly expresses the intent of combining elements.
  • Consistency: Provides a unified syntax for various collection types, making code more predictable.
  • Productivity: Speeds up development by requiring less boilerplate for common collection operations.
  • Performance (for arrays/spans): For arrays and Span<T>, the compiler can often optimize the creation, potentially leading to better performance than Enumerable.Concat or List.AddRange. Collection expressions are a major quality-of-life improvement in C# 12, making code that works with collections cleaner and more efficient.

3. Default Parameters in Lambda Expressions

C# 12 introduces the ability to specify default parameter values directly within lambda expressions. This feature brings lambda expressions closer to the functionality of full methods, enhancing their flexibility and reducing the need for overloads or conditional logic within the lambda body. Problem Solved: Before C# 12, if a lambda expression needed to handle optional parameters or provide default behavior, you would often have to:

1. Define multiple lambda overloads: Not directly possible, you'd define

different lambda expressions or delegates for different numbers of arguments.

2. Use conditional logic: Check for null or specific values within the lambda

body and assign defaults.

3. Define a separate method: Convert the lambda logic into a full method

with default parameters and then reference that method. This could make simple lambda expressions more verbose or less intuitive. Syntax and Behavior: The syntax for default parameters in lambda expressions is identical to that for methods: // C# 12: Default parameter in lambda var greet = (string name = "Guest") => Console.WriteLine($"Hello, {name}!"); // Calling the lambda: // greet(); // Output: Hello, Guest! // greet("Alice"); // Output: Hello, Alice! Key Characteristics and Rules:

  • Syntax: Default parameters are defined by assigning a value directly in the parameter list (e.g., (int x, int y = 10) => ...).
  • Position: Parameters with default values must appear after all required parameters in the lambda's parameter list.
  • Invocation: When calling a lambda with default parameters, you can omit arguments for which default values are provided.
  • Explicit Type: For clarity or when type inference isn't sufficient, you can explicitly specify the type of the lambda using a delegate type (e.g., Action<string> or Func<int, int, int>). This is especially useful if the default value's type can't be inferred solely from its literal.
  • Compile-time Constants: Default values must be compile-time constants. This is the same rule as for default parameters in methods. Real-World Examples: Example 1: Simple Greeting Lambda public static class LambdaDefaultParamsDemo { public static void RunExamples() { Console.WriteLine("--- Default Parameters in Lambda Expressions Demo ---"); // Basic example: Default for a string parameter var greet = (string name = "World") => Console.WriteLine($"Hello, {name}!"); greet(); // Uses default: "World" greet("Alice"); // Uses provided value: "Alice" // Example with multiple parameters, some with defaults var calculateSum = (int a, int b = 5, int c = 10) => a + b + c; Console.WriteLine($"\nSum (10): {calculateSum(10)}"); // a=10, b=5 (default), c=10 (default) -> 25 Console.WriteLine($"Sum (10, 20): {calculateSum(10, 20)}"); // a=10, b=20, c=10 (default) -> 40 Console.WriteLine($"Sum (10, 20, 30): {calculateSum(10, 20, 30)}"); // a=10, b=20, c=30 -> 60 // Explicit delegate type with default parameter Func<string, string, string> formatMessage = (string msg, string prefix = "[LOG]") => $"{prefix} {msg}"; Console.WriteLine($"\n{formatMessage("User logged in.")}"); Console.WriteLine($"{formatMessage("Error occurred.", "[ERROR]")}"); Console.WriteLine("\n--- Default Parameters in Lambda Expressions Demo Finished ---"); } } // Call from Main: // public static void Main(string[] args) // { // LambdaDefaultParamsDemo.RunExamples(); // } Example 2: Event Handling (Conceptual Example) While often handled by method overloads, this demonstrates how a lambda assigned to a delegate could use default parameters. // Define a custom delegate type public delegate void DataProcessedEventHandler(int dataCount, string status = "Completed"); public class DataProcessor { public event DataProcessedEventHandler? DataProcessed; public void SimulateProcessing(int count, string finalStatus = "Completed") { // ... simulate work ... DataProcessed?.Invoke(count, finalStatus); // Can omit finalStatus here for default } public void SimulateProcessingWithoutStatus(int count) { // When invoking, can rely on the default parameter of the event handler DataProcessed?.Invoke(count); } } public static class EventHandlingDemo { public static void RunExample() { Console.WriteLine("\n--- Event Handling with Lambda Default Params Demo ---"); var processor = new DataProcessor(); // Assign a lambda with a default parameter as an event handler processor.DataProcessed += (dataCount, status = "Processed") => { Console.WriteLine($"Event: {dataCount} items {status}."); }; processor.SimulateProcessing(100); // Invokes with "Completed" from SimulateProcessing processor.SimulateProcessing(50, "Failed"); // Invokes with "Failed" processor.SimulateProcessingWithoutStatus(200); // Invokes with "Processed" from the lambda's default Console.WriteLine("\n--- Event Handling with Lambda Default Params Demo Finished ---"); } } // Call from Main: // public static void Main(string[] args) // { // EventHandlingDemo.RunExample(); // } Benefits:
  • Conciseness: Reduces the need for writing overloaded methods or complex conditional logic within the lambda body.
  • Flexibility: Makes lambdas more adaptable to different invocation scenarios.
  • Readability: Clearly defines default behavior directly in the parameter signature.
  • Consistency: Aligns lambda syntax more closely with full method syntax. This feature is a welcome addition that enhances the expressiveness and utility of lambda expressions in C# 12.

4. Alias Any Type

C# 12 extends the using alias directive to allow you to create an alias for any type, including tuple types, pointer types, and array types. Previously, using alias was limited to named types (classes, structs, interfaces, enums, delegates). This enhancement provides greater flexibility for improving code readability, especially when dealing with complex or repetitive type declarations. Problem Solved: Before C# 12, if you had a complex type signature that you used repeatedly, such as a tuple type or a nested array type, you couldn't create a simple alias for it. This often led to:

  • Verbose code: Repeating long type names throughout your code.
  • Reduced readability: Complex type signatures can obscure the intent of the code.
  • Maintenance overhead: If the complex type definition changed, you'd have to update every instance of its usage. Example of old way (pre-C# 12): // Before C# 12, this was not allowed: // using PersonInfo = (string Name, int Age, bool IsStudent); // Compile error! // So you'd have to write the full tuple type repeatedly: public static (string Name, int Age, bool IsStudent) GetPersonData() { return ("Alice", 30, false); } public static void ProcessPerson((string Name, int Age, bool IsStudent) person) { Console.WriteLine($"Name: {person.Name}, Age: {person.Age}, Student: {person.IsStudent}"); } Syntax and Behavior in C# 12: The syntax for aliasing remains the same, but the types you can alias are now greatly expanded: using MyTupleType = (int x, int y); using MyArrayType = string[]; using MyPointerType = unsafe int*; using MyGenericList = System.Collections.Generic.List<string>; // Always allowed // New in C# 12: using PersonInfo = (string Name, int Age, bool IsStudent); using Matrix = double[,]; using ActionList = System.Collections.Generic.List<System.Action<int>>; Key Characteristics and Rules:
  • Broader Scope: You can now alias:
  • Tuple types: Named or unnamed tuples (e.g., (int, string), (string Name, int Age)).
  • Array types: Single-dimensional, multi-dimensional, or jagged arrays (e.g., string[], int[,], byte[][]).
  • Pointer types: (in unsafe contexts) (e.g., int*, void*).
  • Predefined types with complex generics: (e.g., List<Dictionary<string, int>>).
  • Any combination of the above.
  • Declaration Location: using alias directives must be placed at the top of a file, before any namespace or type declarations.
  • Scope of Alias: The alias is only valid within the file where it is declared.
  • No Circular References: You cannot create circular aliases (e.g., using A = B; using B = A;). Real-World Examples: Example 1: Aliasing Tuple Types using ProductDetail = (int Id, string Name, decimal Price); using InventoryStatus = (string Location, int Quantity, DateTime LastUpdated); public class OrderProcessor { public ProductDetail GetProductDetails(int productId) { // Simulate database lookup return (productId, "Laptop", 1200.50m); InventoryStatus inventory = CheckInventory(101); Console.WriteLine($"\n--- Order Information ---"); Console.WriteLine($"Product: {product.Name} (ID: {product.Id}, Price: {product.Price:C})"); Console.WriteLine($"Inventory: {inventory.Quantity} units at {inventory.Location}, last updated {inventory.LastUpdated:g}"); } } // Call from Main: // new OrderProcessor().DisplayOrderInfo(); Example 2: Aliasing Array and Generic Collection Types using Grid = bool[,]; using UserPermissions = System.Collections.Generic.HashSet<string>; using SensorDataStream = System.Collections.Generic.IEnumerable<(DateTime Timestamp, double Value)>; public class ConfigurationManager { public Grid GetFeatureToggleGrid() { // Example: a 2x3 grid of feature toggles Grid toggles = new Grid(2, 3); toggles[0, 0] = true; toggles[1, 2] = true; return toggles; } public UserPermissions GetCurrentUserPermissions() { return new UserPermissions { "read", "write", "delete_self" }; } public SensorDataStream GetLiveSensorData() { // Yield sensor data yield return (DateTime.Now, 25.5); yield return (DateTime.Now.AddSeconds(1), 25.6); yield return (DateTime.Now.AddSeconds(2), 25.7); } public void ShowConfiguration() { Console.WriteLine("\n--- Configuration Details ---"); Grid featureGrid = GetFeatureToggleGrid(); } UserPermissions permissions = GetCurrentUserPermissions(); Console.WriteLine($"\nUser Permissions: [{string.Join(", ", permissions)}]"); Console.WriteLine("\nLive Sensor Data:"); foreach (var data in GetLiveSensorData()) { Console.WriteLine($"- {data.Timestamp:HH:mm:ss}: {data.Value}°C"); } } } // Call from Main: // new ConfigurationManager().ShowConfiguration(); Example 3: Aliasing Pointer Types (Requires unsafe context) // Add <AllowUnsafeBlocks>true</AllowUnsafeBlocks> to your .csproj file using UnmanagedBufferPtr = unsafe byte*; using ImageDimensionsPtr = unsafe int*; public unsafe class UnsafeOperations { public void ProcessRawBuffer() { byte[] buffer = new byte[100]; fixed (byte* pBuffer = buffer) { UnmanagedBufferPtr bufferPtr = pBuffer; // height Console.WriteLine($"Image dimensions set to: {dimensions[0]} x{dimensions[1]}"); } } } // Call from Main (within an unsafe block or unsafe method): // unsafe // { // var unsafeOps = new UnsafeOperations(); // unsafeOps.ProcessRawBuffer(); // unsafeOps.SetImageDimensions(); // } Benefits:
  • Improved Readability: Complex type signatures are replaced with meaningful, concise aliases.
  • Reduced Verbosity: Less typing for frequently used complex types.
  • Easier Maintenance: If a complex type definition changes, you only need to update the using alias directive, not every occurrence in the code.
  • Domain-Specific Naming: Allows developers to create aliases that are more relevant to their domain or problem space, enhancing domain- driven design. Alias any type in C# 12 is a valuable addition for writing cleaner, more maintainable, and highly readable code, especially in projects that frequently deal with complex data structures.

5. Points to Remember

C# 12 continues the trend of blending language enhancements for conciseness and readability with features that provide more control for advanced scenarios. Here are the key takeaways from this version:

1. Primary Constructors in Classes:

  • Purpose: Provides a concise syntax for declaring constructor parameters directly in a class definition.
  • Syntax: public class MyClass(string param1, int param2) { /* ... */ }
  • Key Behavior: Parameters are in scope throughout the entire class body (properties, methods, other constructors). They do not automatically create public properties; you must explicitly define and initialize properties/fields. Secondary constructors must chain to the primary constructor using this(...).
  • Remember: Reduces boilerplate, promotes immutability, and aligns class syntax with records, but be mindful that properties are not automatically generated.

2. Collection Expressions:

  • Purpose: A unified and concise syntax for creating and initializing various collection types.
  • Syntax: Uses square brackets [] for elements.
  • Key Feature (.. Spread Element): Allows inlining elements from existing collections ([.. existingCollection, newItem]).
  • Target-Typed: The compiler infers the collection type from the context (often defaulting to an array if no specific type is given).
  • Remember: Significantly improves readability and reduces verbosity for creating arrays, lists, spans, and other enumerable types, especially when combining them.

3. Default Parameters in Lambda Expressions:

  • Purpose: Enables specifying default values for parameters directly within lambda expressions.
  • Syntax: (int a, int b = 10) => a + b;
  • Key Behavior: Parameters with defaults must appear after all required parameters. Default values must be compile-time constants.
  • Remember: Makes lambdas more flexible, reduces the need for overloads or internal conditional logic, and aligns lambda syntax with regular method parameter syntax.

4. Alias Any Type:

  • Purpose: Extends the using alias directive to allow aliasing of any type, including complex tuple types, array types, and pointer types.
  • Syntax: using MyAlias = (int Id, string Name);
  • Key Benefit: Greatly improves code readability and reduces verbosity for frequently used complex type signatures. Simplifies maintenance if complex type definitions change.
  • Remember: The alias is file-scoped and declared at the top of the file. C# 12 focuses on streamlining common coding patterns, making the language more expressive and concise for everyday tasks, while also providing targeted enhancements for specialized high-performance needs.
