Section 27: File I/O, Streams, Serialization & Encoding

Detailed architectural breakdown integrating comprehensive explanations, syntax reference matrices, compiler internals, and production C# code.

1. Number Systems & Text Encodings (UTF-8 vs UTF-16)

Computers store all information as raw binary bits (0 and 1). Character encodings establish the translation dictionary between human letters and numeric byte representations:

Encoding StandardByte Length per CharacterIndustry Standard Use Case.NET Support
ASCIIExactly 1 byte (7-bit, 0..127)Legacy English-only protocolsEncoding.ASCII
UTF-8Variable: 1 to 4 bytes per code pointThe universal standard for Web APIs, JSON, and filesEncoding.UTF8 (Fastest)
UTF-16Variable: 2 or 4 bytes per code pointInternal in-memory representation for .NET strings and Windows OSEncoding.Unicode
UTF-32Fixed 4 bytes per code pointFixed-width memory indexing; high memory overheadEncoding.UTF32

2. High-Level Filesystem APIs: File, Directory, Path

The System.IO namespace provides static convenience classes for simple file and path operations:

System.IO Static Helper APIs 
using System.IO;

// 1. Cross-platform path combining (handles Windows \ and Linux / automatically)
string configPath = Path.Combine(AppContext.BaseDirectory, "config", "appsettings.json");

// 2. High-level atomic file read/write
await File.WriteAllTextAsync(configPath, "{ "env": "Production" }");
string content = await File.ReadAllTextAsync(configPath);

// 3. Directory inspection
if (Directory.Exists("logs"))
{
    string[] logFiles = Directory.GetFiles("logs", "*.log", SearchOption.AllDirectories);
    Console.WriteLine($"Found {logFiles.Length} log files.");
}

3. Streams Architecture: FileStream, MemoryStream, Readers

When dealing with massive datasets (e.g. 5GB video files or continuous network feeds), reading everything into a single string crashes the application with OutOfMemoryException. Streams process data in small, continuous byte chunks:

📊 Diagram: Stream Processing Architecture
[Physical File on Disk / Socket]
              |
              v (Buffered chunks: 4096 bytes)
+------------------------------------+
| FileStream (Raw Byte Conduit)      |
+------------------------------------+
              |
              v (Decodes bytes -> text)
+------------------------------------+
| StreamReader / StreamWriter        |
+------------------------------------+
              |
              v (Single line processed in memory)
[Application Logic]
High-Efficiency Stream Reading 
// Streaming a large file line-by-line with minimal memory footprint
using var fs = new FileStream("huge_dataset.csv", FileMode.Open, FileAccess.Read);
using var reader = new StreamReader(fs, Encoding.UTF8);

string? line;
int lineCount = 0;
while ((line = await reader.ReadLineAsync()) != null)
{
    lineCount++;
    // Process line without holding entire 5GB file in RAM!
}
Console.WriteLine($"Processed {lineCount} lines safely.");

4. High-Performance JSON Serialization (System.Text.Json)

System.Text.Json is built from the ground up for high throughput, UTF-8 zero-allocation parsing, and native async streaming:

System.Text.Json Serialization 
using System.Text.Json;
using System.Text.Json.Serialization;

public record OrderDto(
    [property: JsonPropertyName("order_id")] int Id,
    [property: JsonPropertyName("customer")] string CustomerName,
    [property: JsonPropertyName("total_amount")] decimal TotalAmount
);

var order = new OrderDto(901, "Alice Smith", 149.99m);

// Configured JSON Options
var options = new JsonSerializerOptions
{
    WriteIndented = true,
    PropertyNameCaseInsensitive = true
};

// Serialize to JSON string
string jsonString = JsonSerializer.Serialize(order, options);
Console.WriteLine(jsonString);

// Deserialize back to strongly-typed record
OrderDto deserialized = JsonSerializer.Deserialize<OrderDto>(jsonString, options)!;

5. File Locking & Encoding Traps

🟠 Compiler Trap & Common Gotcha

Bug: Opening a file with default constructor locks the file exclusively: 

using var s1 = new FileStream("data.txt", FileMode.Open);
using var s2 = new FileStream("data.txt", FileMode.Open); // IOException: The process cannot access the file!

Fix: Specify sharing permissions explicitly when multiple readers exist: FileShare.ReadWrite.
