Section 05: Fields & Access Modifiers

Detailed architectural breakdown integrating comprehensive explanations, syntax reference matrices, compiler internals, and production C# code.

1. What are Fields & Instance State

Fields are variables declared directly within the body of a class. They represent the data, attributes, or state of an object instance. If a class is a blueprint for a Product, the fields are the individual slots for productId, unitPrice, and stockQuantity.

2. Access Modifiers: The Encapsulation Matrix

Access modifiers control the visibility and accessibility boundaries of types and type members. Encapsulation dictates that internal fields should generally be shielded from outside interference.

ModifierAccessible Where?Assembly ScopePrimary Architectural Role
privateOnly within the containing class bodyLocal to classDefault for class members. Encapsulates private internal state.
publicEverywhere; no restrictionsUniversalExposes the public contract and API interface.
protectedContaining class and derived sub-classesAcross assemblies via inheritanceAllows child classes to specialize or access base internals.
internalAny code within the same compilation assembly (.dll)Same assembly onlyHides implementation details from external consumers while sharing across project files.
protected internalAny class in same assembly OR derived classes in any assemblySame assembly + derivedUnion of protected and internal.
private protectedOnly derived classes located within the same assemblySame assembly derived onlyIntersection of private and protected (C# 7.2+).

3. Readonly vs Const Fields

Both const and readonly prevent values from being mutated after initialization, but their underlying compiler mechanics are radically different:

Feature<code>const</code> Field<code>readonly</code> Field
Evaluation TimingEvaluated at compile timeEvaluated at runtime
Memory AllocationNever allocated memory; compiler inlines literal value directly into calling IL instructionsAllocated memory in the object payload or static type block
Initialization PlaceOnly at declaration line: const int Max = 100;At declaration OR inside a constructor: readonly DateTime Created;
Allowed TypesOnly primitive numbers, bool, char, string, or nullAny C# type (including complex objects, arrays, and structs)
Versioning RiskSevere: If assembly A references a const in assembly B, changing the const requires recompiling assembly A!Zero: Assembly A reads the runtime value from assembly B dynamically.
Const vs Readonly in Practice 
public class Order
{
    // Compile-time constant (inlined everywhere at compile time)
    public const decimal DefaultTaxRate = 0.0825m;

    // Runtime immutable instance field (set during object construction)
    public readonly string OrderId;
    public readonly DateTime CreatedTimestamp;

    // Standard mutable instance fields
    private decimal _subtotal;

    public Order(string orderId, decimal subtotal)
    {
        OrderId = orderId;                     // Valid: inside constructor
        CreatedTimestamp = DateTime.UtcNow;    // Valid: dynamic runtime value
        _subtotal = subtotal;
    }

    public void AttemptMutation()
    {
        // OrderId = "NEW-123"; // CS0191: A readonly field cannot be assigned to (except in a constructor)
    }
}

4. Static Fields & Shared Class Memory

When a field is decorated with the static keyword, it belongs to the class itself, not to any individual instance. The CLR allocates static field memory in the high-frequency heap when the class is first loaded:

Static vs Instance Fields 
public class UserSession
{
    // Static field: exactly ONE copy shared across all instances
    public static int ActiveSessionCount = 0;

    // Instance field: every object has its own separate username
    public string Username;

    public UserSession(string username)
    {
        Username = username;
        ActiveSessionCount++; // Increment global counter
    }
}

5. Field Memory Isolation & Default Values

When an object is allocated, all fields are guaranteed to be initialized to their CTS default values before any constructor logic runs:

  • Numeric types (byte, int, long, double, decimal) → 0
  • Boolean (bool) → false
  • Character (char) → '\0' (null char)
  • Reference types (string, class, object) → null

6. Field Encapsulation Traps

🟠 Compiler Trap & Common Gotcha

Anti-Pattern: Exposing mutable state directly: public decimal Balance;.

Consequence: Any external consumer can write acc.Balance = -999999m; with zero validation, invalidating internal invariants.

Architecture Rule: Keep fields private or protected. Use Properties to provide guarded access, validation, and change notifications.
