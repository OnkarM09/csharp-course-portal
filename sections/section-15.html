System.Object ToString() Equals() GetHashCode() GetType()

Section 15: System.Object & Core Method Overrides

Detailed architectural breakdown integrating comprehensive explanations, syntax reference matrices, compiler internals, and production C# code.

1. System.Object: The Universal Ancestor

In the .NET type hierarchy, System.Object (aliased by the C# keyword object) is the root ancestor from which every single type directly or indirectly inherits. This design unifies the entire language, allowing any data structure to be passed, inspected, or boxed via a common abstraction.

2. Boxing & Unboxing Mechanics & Memory Layout

Boxing is the process of converting a value type (like int or a struct) into a reference type by wrapping it inside an object instance allocated on the managed heap:

📊 Diagram: Boxing & Unboxing Memory Lifecycle
STACK FRAME:                                        MANAGED HEAP:
+-----------------------------------+               +--------------------------------------+
| [int] val = 42                    | (Direct Value)|                                      |
|                                   |               | Address: 0x00F890                    |
| [object] boxedRef --(Pointer)-----+---------------+-> [Type: System.Int32 MethodTable]  |
|                                   |               |   [SyncBlock Index: 0]               |
|                                   |               |   [Payload Value: 42] (Allocated!)   |
| [int] unboxedVal = 42             | <-------------+--------------------------------------+
+-----------------------------------+               (Unboxing extracts value back to stack)

3. Overriding ToString() for Readable Representation

By default, ToString() returns the fully qualified namespace and type name (e.g. MyCompany.App.Customer). Overriding it provides clean debugging and logging:

ToString() Override 
public class Product
{
    public string Sku { get; init; }
    public decimal Price { get; init; }

    public override string ToString() => $"Product [SKU: {Sku}, Price: {Price:C}]";
}

4. Value Equality vs Reference Equality (Equals)

By default, Equals() for classes tests reference equality (do both variables point to the exact same heap address?). To test if two distinct instances represent the same logical domain entity, override Equals and implement IEquatable<T>:

Complete Robust Equality Implementation 
public class Product : IEquatable<Product>
{
    public string Sku { get; init; }
    public decimal Price { get; init; }

    public bool Equals(Product? other)
    {
        if (other is null) return false;
        if (ReferenceEquals(this, other)) return true;
        return Sku == other.Sku;
    }

    public override bool Equals(object? obj) => Equals(obj as Product);

    public override int GetHashCode() => Sku.GetHashCode(StringComparison.OrdinalIgnoreCase);

    public static bool operator ==(Product? left, Product? right) => Equals(left, right);
    public static bool operator !=(Product? left, Product? right) => !Equals(left, right);
}

5. The GetHashCode() Contract & Hash Tables

If two objects are considered equal according to Equals(), they MUST return the exact same integer hash code from GetHashCode()!

🟠 Compiler Trap & Common Gotcha

If you override Equals but fail to override GetHashCode, storing instances in a HashSet<T> or Dictionary<TKey, TValue> will fail catastrophically: duplicate items will be added, or existing items will become completely unfindable!

6. GetType() & Runtime Type Inspection

The GetType() method is non-virtual and returns the exact runtime System.Type metadata handle of the object, enabling deep reflection:

GetType() Reflection Probe 
object data = "Hello World";
Type t = data.GetType();
Console.WriteLine(t.FullName); // System.String
Console.WriteLine(t.IsValueType); // False

7. Common Object Overriding Traps

🟠 Compiler Trap & Common Gotcha

Fatal Bug: Using a mutable field in GetHashCode().

If an object is placed into a HashSet<Customer>, and you subsequently change customer.Id = 999;, its hash code changes. The hash table will now look in the wrong bucket when searching for the customer, making it impossible to remove or find!

Rule: Fields contributing to GetHashCode() must be strictly immutable (readonly or init).
