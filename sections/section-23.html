Section 23: Anonymous Types

Detailed architectural breakdown integrating comprehensive explanations, syntax reference matrices, compiler internals, and production C# code.

1. What Are Anonymous Types & Ephemeral DTOs

An anonymous type provides a clean, concise way to encapsulate a set of read-only properties into a single object without having to explicitly define a formal class first. They are declared using the new { ... } syntax with var:

Anonymous Type Syntax 
var userSummary = new 
{ 
    Id = 101, 
    Username = "octocat", 
    IsActive = true,
    LoginTime = DateTime.UtcNow 
};

Console.WriteLine($"User: {userSummary.Username}, Active: {userSummary.IsActive}");

2. Under the Hood: Roslyn Synthetic Class Generation

🟣 Under the Hood / Compiler Lowering

When you write new { Id = 101, Username = "octocat" }, the compiler automatically generates a hidden internal generic class: 

[CompilerGenerated]
internal sealed class <>f__AnonymousType0<<Id>j__TPar, <Username>j__TPar>
{
    private readonly <Id>j__TPar <Id>i__Field;
    private readonly <Username>j__TPar <Username>i__Field;

    public <Id>j__TPar Id => <Id>i__Field;
    public <Username>j__TPar Username => <Username>i__Field;

    public override bool Equals(object value) { /* ... */ }
    public override int GetHashCode() { /* ... */ }
    public override string ToString() { /* ... */ }
}

If two anonymous types in the same assembly share the exact same property names and types in the exact same order, the compiler reuses the exact same synthetic class!

3. Read-Only Immutability & Value Equality

Properties on anonymous types are strictly read-only. Furthermore, the compiler overrides Equals() and GetHashCode() to provide value-based equality:

Anonymous Type Value Equality 
var p1 = new { Sku = "SKU-99", Price = 19.99m };
var p2 = new { Sku = "SKU-99", Price = 19.99m };

// Value equality evaluates to TRUE even though they are distinct heap objects!
Console.WriteLine(p1.Equals(p2)); // True
Console.WriteLine(p1 == p2);      // False (== performs reference equality for classes)

4. LINQ Select Projections with Anonymous Types

Anonymous types shine brightest when projecting database columns or large domain entities in LINQ queries:

LINQ Projection 
var activeOrders = dbContext.Orders
    .Where(o => o.IsPending)
    .Select(o => new 
    {
        o.OrderId,
        CustomerName = o.Customer.FullName,
        ItemCount = o.Items.Count
    })
    .ToList();

5. Limitations & Method Boundary Traps

🟠 Compiler Trap & Common Gotcha

Limitation: You cannot declare a method return type as an anonymous type: 

public var GetCustomer() { ... } // ILLEGAL in C#!

Returning an anonymous type forces the return type to be object, stripping all property IntelliSense. For public API boundaries, use modern C# Tuples or Records instead.
