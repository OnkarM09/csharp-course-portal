Section 11: Abstract Classes & Interfaces

Detailed architectural breakdown integrating comprehensive explanations, syntax reference matrices, compiler internals, and production C# code.

1. The Essence of Abstraction

Abstraction is the discipline of hiding internal system complexity while exposing only the essential, high-level functional interface. It enables architects to separate what an object does from how it accomplishes it.

🔵 Core Concept (from Notes)

When you drive a car, you press down on the accelerator pedal to increase speed. You do not need to calculate cylinder fuel injection ratios, spark plug timing, or manifold air pressure. The pedal provides an abstract contract: apply pressure → vehicle accelerates.

2. Abstract Classes & Abstract Methods

An abstract class cannot be directly instantiated with new. It serves as an incomplete base template designed to be extended by concrete sub-classes:

Abstract Class Implementation 
public abstract class PaymentProcessor
{
    // Concrete field and implemented helper method
    public string MerchantId { get; init; }

    public void LogTransaction(string txId) => 
        Console.WriteLine($"[AUDIT] Merchant {MerchantId} recorded Tx {txId}");

    // Pure abstract method: MUST be implemented by any concrete child class
    public abstract bool ProcessPayment(decimal amount, string currency);
}

public class StripePaymentProcessor : PaymentProcessor
{
    public override bool ProcessPayment(decimal amount, string currency)
    {
        Console.WriteLine($"Charging {amount} {currency} via Stripe Gateway.");
        LogTransaction(Guid.NewGuid().ToString("N"));
        return true;
    }
}

3. Interfaces: Pure Architectural Contracts

An interface defines a pure behavioral contract. A class or struct implementing an interface agrees to fulfill every member specified by that contract. While a C# class can inherit from only one base class, it can implement multiple interfaces:

Multiple Interface Implementation 
public interface IRepository<T>
{
    Task<T?> GetByIdAsync(int id);
    Task<IEnumerable<T>> GetAllAsync();
    Task AddAsync(T entity);
}

public interface IAuditable
{
    string CreatedBy { get; set; }
    DateTime CreatedAtUtc { get; set; }
}

// Multiple interface implementation:
public class CustomerRepository : IRepository<Customer>, IAuditable
{
    public string CreatedBy { get; set; } = "System";
    public DateTime CreatedAtUtc { get; set; } = DateTime.UtcNow;

    public async Task<Customer?> GetByIdAsync(int id) { /* ... */ return null; }
    public async Task<IEnumerable<Customer>> GetAllAsync() { /* ... */ return []; }
    public async Task AddAsync(Customer entity) { /* ... */ }
}

4. Abstract Class vs Interface Comparison Matrix

Architectural CharacteristicAbstract ClassInterface
Multiple InheritanceNo (Single base class inheritance only)Yes (A class can implement unlimited interfaces)
Instance State / FieldsYes (Can declare private, protected, and public instance fields)No (Cannot contain instance state or instance fields)
Access ModifiersFull spectrum (private, protected, internal, public)Traditionally all public (can have internal/private in modern DIM)
ConstructorsYes (Can declare parameterized base constructors)No (Interfaces cannot have constructors)
Speed / DispatchStandard vtable dynamic dispatch (very fast)Interface table (itable) lookup (minimal extra indirection)
Design HeuristicModels core ontological identity ("What the object IS")Models peripheral capabilities ("What the object CAN DO")

5. Explicit Interface Implementation

When a class implements two interfaces that declare the exact same method signature, Explicit Interface Implementation resolves the conflict cleanly:

Explicit Interface Implementation 
public interface ISaveable { void Save(); }
public interface IExportable { void Save(); }

public class Document : ISaveable, IExportable
{
    // Explicit implementation: does NOT have a public access modifier!
    void ISaveable.Save() => Console.WriteLine("Saving to local database.");
    void IExportable.Save() => Console.WriteLine("Exporting file to disk.");
}

// Caller usage requires casting to the specific interface:
var doc = new Document();
// doc.Save(); // CS1061: 'Document' does not contain a definition for 'Save'

((ISaveable)doc).Save();   // Prints: Saving to local database.
((IExportable)doc).Save(); // Prints: Exporting file to disk.

6. Modern Default Interface Methods (DIM)

Since C# 8, interfaces can provide default method implementations. This allows library authors to add new methods to an existing interface without breaking existing third-party implementers:

Default Interface Method 
public interface ILogger
{
    void Log(string message);

    // Default interface method (DIM):
    void LogError(Exception ex) => Log($"[ERROR] {ex.Message}");
}

7. Common Abstraction Traps

🟠 Compiler Trap & Common Gotcha

Trap: Default interface methods are not inherited by the implementing class's public interface. 

ILogger logger = new ConsoleLogger();
logger.LogError(new Exception()); // OK!

ConsoleLogger concrete = new ConsoleLogger();
concrete.LogError(new Exception()); // CS1061 Error! Must cast to ILogger!
