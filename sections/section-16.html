Section 16: Generics (Classes, Methods, Constraints)

Detailed architectural breakdown integrating comprehensive explanations, syntax reference matrices, compiler internals, and production C# code.

1. The Problem Generics Solved: ArrayList vs Type Safety

In early .NET 1.x before Generics were introduced in C# 2.0, the only way to write reusable data structures was to cast everything to System.Object (as in the legacy ArrayList or Hashtable). This caused two catastrophic problems:

🔵 Core Concept (from Notes)
  1. Massive Boxing Overhead: Storing value types (like int) in an ArrayList required boxing them onto the heap on every insert and unboxing on every read, devastating performance and generating millions of GC objects.
  2. Total Loss of Type Safety: An ArrayList could hold integers, strings, and customers simultaneously: 
    ArrayList list = new ArrayList();
list.Add(42);
list.Add("Hello"); // Compiles cleanly!
int val = (int)list[1]; // System.InvalidCastException at RUNTIME!

Generics solved this permanently: you write the algorithm once using a placeholder type T, and the compiler enforces strict compile-time type safety with zero boxing overhead.

2. Generic Classes & The Type Parameter T

Custom Generic Class 
// A high-performance, type-safe custom generic circular buffer
public class CircularBuffer<T>
{
    private readonly T[] _buffer;
    private int _head = 0;
    private int _tail = 0;
    private int _count = 0;

    public int Capacity => _buffer.Length;
    public int Count => _count;

    public CircularBuffer(int capacity)
    {
        if (capacity <= 0) throw new ArgumentOutOfRangeException(nameof(capacity));
        _buffer = new T[capacity];
    }

    public void Enqueue(T item)
    {
        _buffer[_tail] = item;
        _tail = (_tail + 1) % Capacity;
        if (_count < Capacity) _count++;
        else _head = (_head + 1) % Capacity; // Overwrite oldest item
    }

    public T Dequeue()
    {
        if (_count == 0) throw new InvalidOperationException("Buffer is empty.");
        T item = _buffer[_head];
        _buffer[_head] = default!; // Clear reference for GC
        _head = (_head + 1) % Capacity;
        _count--;
        return item;
    }
}

3. Generic Methods & Type Inference

Methods can declare their own generic type parameters independently of the containing class. The compiler usually infers the type automatically:

Generic Method with Type Inference 
public static class ArrayUtilities
{
    // Generic swap method with pass-by-reference
    public static void Swap<T>(ref T a, ref T b)
    {
        T temp = a;
        a = b;
        b = temp;
    }
}

// Caller usage:
int x = 10, y = 20;
ArrayUtilities.Swap(ref x, ref y); // Compiler automatically infers T = int!

4. The Generic Constraints (where) Matrix

By default, T can be literally any type. Constraints restrict what types can be passed, allowing your method to invoke members on T:

Constraint SyntaxType RestrictionEnables Inside Generic Body
where T : structMust be a non-nullable Value TypeGuarantees value semantics; stack allocation; cannot be null.
where T : classMust be a Reference TypeAllows comparison with null.
where T : new()Must have a public parameterless constructorEnables calling new T() inside generic code!
where T : BaseClassMust inherit from the specified base classDirect access to all base class properties and methods.
where T : IComparable<T>Must implement the specified interfaceDirect access to interface contract members.
where T : notnullMust be non-nullable (C# 8+)Enforces null safety in modern NRT mode.
where T : unmanagedMust be a struct containing no reference fieldsAllows native memory pinning and raw pointer manipulation.
Multiple Generic Constraints 
// Combining multiple generic constraints
public class EntityStore<T> 
    where T : class, IComparable<T>, new()
{
    public T CreateDefaultSortedItem(T baseline)
    {
        T item = new T(); // Legal because of new()
        if (item.CompareTo(baseline) > 0) // Legal because of IComparable<T>
        {
            return item;
        }
        return baseline;
    }
}

5. CLR JIT Specialization: Value Types vs Reference Types

How does RyuJIT execute generic code without performance penalties?

🟣 Under the Hood / Compiler Lowering
  • For Value Types (List<int>, List<double>): The JIT generates a completely separate, dedicated native machine code copy for each distinct value type. The memory slots are sized exactly to 4 bytes or 8 bytes with direct CPU instructions and zero boxing.
  • For Reference Types (List<string>, List<Customer>): Because all references in 64-bit .NET are identical 8-byte pointer addresses, the JIT shares a single canonical native implementation across all reference types, saving massive amounts of memory.

6. Covariance (out) and Contravariance (in)

Variance dictates how subtyping between more complex types relates to subtyping between their components:

Variance TypeKeywordDirectionStandard Interface ExampleAllows Assignment
Covariantout TOutput only (returns T)IEnumerable<out T>IEnumerable<Animal> a = new List<Dog>(); (Dog is an Animal)
Contravariantin TInput only (accepts T as param)IComparable<in T>, Action<in T>IComparable<Dog> comp = animalComparer; (Can compare Dogs with general Animal logic)
InvariantNoneBoth Input & OutputIList<T>, List<T>Must match exact type: List<Animal> != List<Dog>

7. Common Generics Gotchas

🟠 Compiler Trap & Common Gotcha

Error: Writing if (a == b) on an unconstrained T triggers compiler error CS0019: Operator '==' cannot be applied to operands of type 'T' and 'T'.

Fix: Use EqualityComparer<T>.Default.Equals(a, b) or constrain where T : IEquatable<T>.
