Section 02: C# Language Basics & Syntax

Detailed architectural breakdown integrating comprehensive explanations, syntax reference matrices, compiler internals, and production C# code.

1. CTS Data Types & Value vs Reference Memory

C# is an uncompromisingly statically-typed language. Every variable, constant, and expression evaluates to a known type at compile time. The runtime verifies that data placed into memory adheres strictly to the layout rules dictated by the Common Type System (CTS).

🔵 Core Concept (from Notes)

In dynamically typed languages, assigning text to a numeric variable often succeeds silently until runtime calculations explode in production. In C#, assigning a string literal to an int triggers an instant compilation block: 

int age = "twenty"; // CS0029: Cannot implicitly convert type 'string' to 'int'

This compile-time safety acts as a vigilant quality control engineer, permanently preventing an entire class of runtime memory corruption bugs.

3. Variable Declarations, Constants & Scoping

In C#, variables must be declared before use. Variables declared within a method block { ... } have local scope and cannot be accessed outside that block.

Variable Scoping & Constants 
// Explicit vs Type-Inferred local declaration
int userAge = 28;                  // Explicit typing
var accountBalance = 1500.50m;     // Compiler infers decimal! (STILL statically typed)

// Compile-time constants vs Read-only values
const double Pi = 3.141592653589793; // Evaluated at compile-time, inlined into IL
readonly DateTime BootTime;          // Evaluated at runtime during initialization

// Scope Demonstration
{
    int localScopeOnly = 42;
    Console.WriteLine(localScopeOnly);
}
// Console.WriteLine(localScopeOnly); // CS0103: The name 'localScopeOnly' does not exist in current context

5. Decision & Loop Control Structures

Branching & Looping Primitives 
int statusCode = 404;

// 1. Classical Branching
if (statusCode == 200)
{
    Console.WriteLine("OK");
}
else if (statusCode == 404)
{
    Console.WriteLine("Resource Not Found");
}
else
{
    Console.WriteLine("Unhandled code");
}

// 2. High-Performance Loop Constructs
int[] numbers = [10, 20, 30, 40, 50];

// Standard For loop (indexed)
for (int i = 0; i < numbers.Length; i++)
{
    Console.WriteLine($"Index {i}: {numbers[i]}");
}

// Foreach loop (clean iteration over IEnumerable)
foreach (var num in numbers)
{
    if (num == 30) continue; // Skip to next iteration
    Console.WriteLine($"Value: {num}");
}

6. Static Typing & Roslyn Diagnostic Safety

Because C# is statically typed, using var does NOT introduce dynamic typing! The compiler determines the exact type from the right-hand initialization expression at compile time and writes the explicit type into the CIL metadata:

🟣 Under the Hood / Compiler Lowering

When you write: 

var message = "Hello World";

The Roslyn compiler emits identical CIL instructions as writing: 

string message = "Hello World";

There is zero runtime type inspection, zero reflection overhead, and zero performance penalty.

7. Common Syntax Pitfalls

🟠 Compiler Trap & Common Gotcha

Bug: Using double price = 0.1; double tax = 0.2; and expecting price + tax == 0.3 to be true.

Reality: Base-2 IEEE 754 floating points cannot represent 0.1 or 0.2 exactly. The result is 0.30000000000000004. For e-commerce, banking, taxes, and accounting, ALWAYS use decimal (e.g., 0.1m + 0.2m == 0.3m).
