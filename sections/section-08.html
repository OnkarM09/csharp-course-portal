Section 08: Constructors (Basics & Chaining)

Detailed architectural breakdown integrating comprehensive explanations, syntax reference matrices, compiler internals, and production C# code.

1. Role of Constructors & Object Initialization

An instance constructor is a special member method invoked automatically whenever an object is instantiated via the new operator. Its primary duty is to establish the object's invariants—ensuring that the newly minted object starts its lifecycle in a valid, cohesive, and usable state.

🔵 Core Concept (from Notes)

Constructors adhere to two strict syntactic mandates:

  1. They must bear the exact same name as the enclosing class.
  2. They have no return type whatsoever—not even void. Returning a value from a constructor is illegal.

2. The Default Parameterless Constructor

If a class contains zero explicit constructor declarations, the C# compiler automatically injects an invisible, parameterless constructor:

🟣 Under the Hood / Compiler Lowering

When you write: 

public class Customer { }

The Roslyn compiler automatically generates: 

public class Customer
{
    public Customer() : base()
    {
    }
}

Crucial Rule: The instant you declare any custom constructor with parameters (e.g. public Customer(string name)), the compiler permanently revokes the automatic default constructor! If callers still need new Customer(), you must explicitly declare it.

3. Parameterized Constructors & Overloading

Constructors can be overloaded to provide multiple convenient mechanisms for instantiating an object:

Overloaded Constructors 
public class Employee
{
    public int Id { get; set; }
    public string Name { get; set; }
    public string Department { get; set; }
    public decimal Salary { get; set; }

    // Constructor 1: Fully parameterized
    public Employee(int id, string name, string department, decimal salary)
    {
        Id = id;
        Name = name;
        Department = department;
        Salary = salary;
    }

    // Constructor 2: Overload providing defaults
    public Employee(int id, string name)
    {
        Id = id;
        Name = name;
        Department = "General";
        Salary = 40_000m;
    }
}

4. Constructor Chaining with this() and base()

In the example above, initializing fields across multiple constructors duplicates code and violates DRY (Don't Repeat Yourself). Constructor chaining allows one constructor to invoke another constructor within the same class using this(...):

Constructor Chaining with this() 
public class Employee
{
    public int Id { get; }
    public string Name { get; }
    public string Department { get; }
    public decimal Salary { get; }

    // Master / Canonical Constructor
    public Employee(int id, string name, string department, decimal salary)
    {
        Id = id;
        Name = name;
        Department = department;
        Salary = salary;
    }

    // Chained constructor: delegates to master constructor with defaults
    public Employee(int id, string name) 
        : this(id, name, "General", 40_000m)
    {
        // Any secondary initialization specific to this overload executes AFTER this(...)
    }

    // Another chained overload
    public Employee(int id) 
        : this(id, "Unknown Worker")
    {
    }
}

5. Static Constructors & Thread-Safe Loading

A static constructor initializes static fields and executes exactly once per application lifetime—before the first instance is created or any static member is accessed:

  • Has no access modifiers (cannot be marked public or private).
  • Cannot accept parameters.
  • Guaranteed by the CLR to execute thread-safely without requiring manual locks.
Static Constructor 
public class DatabaseConfig
{
    public static readonly string ConnectionString;

    // Static constructor executes once automatically
    static DatabaseConfig()
    {
        ConnectionString = "Server=prod-sql;Database=CoreDb;Trusted_Connection=True;";
        Console.WriteLine("Static DatabaseConfig initialized.");
    }
}

6. Private Constructors & The Singleton Pattern

Declaring a constructor with private prevents external code from creating instances with new. This is common in the Singleton Pattern:

Thread-Safe Singleton with Private Constructor 
public sealed class ApplicationCache
{
    // Thread-safe Lazy Singleton instance
    private static readonly Lazy<ApplicationCache> _instance = 
        new Lazy<ApplicationCache>(() => new ApplicationCache());

    public static ApplicationCache Instance => _instance.Value;

    // Private constructor: blocks external instantiation
    private ApplicationCache()
    {
        Console.WriteLine("ApplicationCache initialized.");
    }

    public void Store(string key, object val) { /* ... */ }
}

7. Common Constructor Traps

🟠 Compiler Trap & Common Gotcha

Severe Trap: Invoking a virtual method inside a base class constructor.

Under the Hood: The derived class's override runs before the derived class's constructor body has executed! If the overridden method accesses fields in the derived class, they will be uninitialized (e.g. null), causing subtle crashes.

Rule: Keep constructors clean. Never call virtual or abstract methods from within a constructor.
