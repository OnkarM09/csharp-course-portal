Section 07: Type Conversion & Casting

Detailed architectural breakdown integrating comprehensive explanations, syntax reference matrices, compiler internals, and production C# code.

1. Conversion Categories: Implicit vs Explicit

Because C# is strictly typed, converting a variable from one data type to another requires clear rules regarding safety and data preservation:

Conversion CategoryDirection / OperationSafety & Data LossSyntax RequiredExample
Implicit ConversionNarrower type → Broader type (Widening)Guaranteed 100% safe; no loss of magnitudeNone; handled automatically by compilerint small = 42; long big = small;
Explicit CastBroader type → Narrower type (Narrowing)Unsafe; truncation or integer overflow possibleExplicit cast operator (targetType)double d = 9.99; int i = (int)d; // i is 9
Helper MethodsUnrelated types (e.g. string to int)Throws exceptions if format invalidConvert.ToInt32(), int.Parse()int val = int.Parse("123");
Defensive ParsingString to primitive without throwing100% safe; returns boolean statusint.TryParse(str, out val)int.TryParse("42", out int val);

2. Numeric Widening vs Narrowing Diagram

📊 Diagram: Numeric Hierarchy: Safe Widening vs Potentially Truncating Narrowing
SAFE IMPLICIT WIDENING (No data loss):
byte (8-bit) ---> short (16-bit) ---> int (32-bit) ---> long (64-bit) ---> decimal / double
[0..255]          [-32k..+32k]        [-2.1B..+2.1B]    [-9 Quint..+9 Quint]

POTENTIALLY DESTRUCTIVE EXPLICIT CAST (Narrowing):
long (64-bit) ---(cast)---> int (32-bit) ---(cast)---> byte (8-bit)
(If value exceeds 255, bits are chopped or OverflowException is thrown!)

3. Overflow Handling: checked vs unchecked

By default in C#, integer arithmetic that overflows wraps around silently without throwing an exception:

checked vs unchecked Arithmetic 
int max = int.MaxValue; // 2,147,483,647

// Silent overflow (default behavior in unchecked context):
int wrapped = max + 1;
Console.WriteLine(wrapped); // Outputs: -2147483648 ! (Wraps around to MinValue)

// Enforcing overflow safety with 'checked':
try
{
    checked
    {
        int safeVal = max + 1; // Throws System.OverflowException!
    }
}
catch (OverflowException ex)
{
    Console.WriteLine($"Caught overflow protection: {ex.Message}");
}

4. System.Convert Helper Class

The System.Convert class converts between base CTS data types and rounds floating points to the nearest even integer (Banker's Rounding):

System.Convert Usage 
string textVal = "12345";
int convertedInt = Convert.ToInt32(textVal);

double floatVal = 4.6;
int roundedInt = Convert.ToInt32(floatVal); // Rounds to 5 (Banker's rounding)

// Convert handles null gracefully by returning 0
string nullStr = null;
int fromNull = Convert.ToInt32(nullStr); // Returns 0, does NOT throw!

5. String Parsing: Parse() vs TryParse() Pattern

Converting user-supplied strings into numbers is a ubiquitous programming task. There is a profound performance and resilience difference between Parse and TryParse:

ApproachSyntaxOn Valid InputOn Malformed InputPerformance Profile
int.Parseint.Parse(str)Returns integerThrows FormatException or ArgumentNullExceptionCostly on error (stack unwinding)
int.TryParseint.TryParse(str, out int val)Returns true, outputs valueReturns false, outputs 0Ultra-fast (zero exceptions thrown)
Robust TryParse Pattern 
// The Industry-Standard Defensive Parsing Pattern
string rawInput = "450";

if (int.TryParse(rawInput, out int parsedSpeed))
{
    Console.WriteLine($"Successfully parsed vehicle speed: {parsedSpeed} km/h");
}
else
{
    Console.WriteLine("Invalid numeric speed provided.");
}

6. User-Defined explicit and implicit Operators

You can define custom conversion operators between your custom domain classes using implicit operator and explicit operator:

Custom Conversion Operators 
public readonly struct Currency
{
    public decimal Amount { get; }

    public Currency(decimal amount) => Amount = amount;

    // Implicit conversion from decimal to Currency (safe)
    public static implicit operator Currency(decimal d) => new Currency(d);

    // Explicit conversion from Currency to double (loss of exact decimal precision)
    public static explicit operator double(Currency c) => (double)c.Amount;
}

7. Common Casting Traps

🟠 Compiler Trap & Common Gotcha

Trap: Writing int val = int.Parse(null); throws ArgumentNullException, whereas int val = (int)objectRef; throws NullReferenceException if objectRef is null.

Best Practice: Always validate strings with !string.IsNullOrWhiteSpace() or use TryParse. For reference casting, use the safe is pattern: if (obj is Customer c) { ... }.
