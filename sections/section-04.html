OOP Classes Objects Instantiating Memory Allocation

Section 04: OOP Basics (Classes & Objects)

Detailed architectural breakdown integrating comprehensive explanations, syntax reference matrices, compiler internals, and production C# code.

1. Procedural vs Object-Oriented Paradigm

Before Object-Oriented Programming (OOP), the dominant development model was procedural programming. In procedural systems, an application is structured as a series of sequential subroutines or functions operating upon detached global or shared data structures. While straightforward for tiny scripts, procedural architectures inevitably suffer from severe friction as codebases scale:

🔵 Core Concept (from Notes)

In procedural systems, because functions across the entire codebase directly touch and modify the same data records, modifying a single field often triggers unpredictable cascading bugs across unrelated modules—a phenomenon known as spaghetti code.

OOP solves this foundational problem by binding data (state / fields) and the operations acting on that data (behavior / methods) together into self-governing conceptual units called objects. The outside world cannot arbitrarily manipulate the object's internal memory; it must send messages through controlled public interfaces.

2. The Class as an Architectural Blueprint

A class is the architectural schematic or template written by the software engineer in source code. It specifies what data fields an object will hold and what operations it can execute. A class does not occupy memory for instance data until it is instantiated:

BankAccount Class Definition 
// Defining an architectural blueprint for a Bank Account
public class BankAccount
{
    // Fields: State / Attributes
    public string AccountNumber;
    public string AccountHolder;
    public decimal CurrentBalance;

    // Methods: Behavior / Actions
    public void Deposit(decimal amount)
    {
        if (amount <= 0)
        {
            Console.WriteLine("Deposit amount must be positive.");
            return;
        }
        CurrentBalance += amount;
        Console.WriteLine($"Deposited {amount:C}. New Balance: {CurrentBalance:C}");
    }

    public void Withdraw(decimal amount)
    {
        if (amount > CurrentBalance)
        {
            Console.WriteLine("Insufficient funds for withdrawal.");
            return;
        }
        CurrentBalance -= amount;
        Console.WriteLine($"Withdrew {amount:C}. Remaining: {CurrentBalance:C}");
    }
}

3. Instantiating Objects with the "new" Operator

When you invoke new BankAccount(), the CLR performs four discrete low-level operations:

  1. Calculates Size: Computes the exact byte footprint required for all instance fields plus internal object overhead (Type Handle + SyncBlock Index).
  2. Allocates Heap Memory: Claims contiguous bytes on the CLR Managed Heap and zeroes the memory (defaulting numbers to 0, references to null).
  3. Initializes Object Header: Writes the pointer to the class's MethodTable (used for dynamic dispatch and runtime type identification).
  4. Returns Reference Pointer: Returns the memory address of the newly allocated heap block to the stack variable.

5. Object Isolation & Multiple Instances

Every object instantiated from a class is entirely isolated from other instances. Modifying account1.CurrentBalance has zero impact on account2.CurrentBalance:

Object Isolation in Action 
var acc1 = new BankAccount();
acc1.AccountNumber = "ACC-101";
acc1.AccountHolder = "Alice";
acc1.Deposit(1000m);

var acc2 = new BankAccount();
acc2.AccountNumber = "ACC-102";
acc2.AccountHolder = "Bob";
acc2.Deposit(250m);

Console.WriteLine($"Acc 1 Balance: {acc1.CurrentBalance:C}"); // $1,000.00
Console.WriteLine($"Acc 2 Balance: {acc2.CurrentBalance:C}"); // $250.00

6. Object Lifetime & CLR Garbage Collection

In C#, you never call free() or delete. When an object on the heap no longer has any active references pointing to it from running stack frames, static variables, or CPU registers, it becomes eligible for automatic Garbage Collection (GC). The GC reclaims the heap memory automatically in the background.

7. Common OOP Gotchas

🟠 Compiler Trap & Common Gotcha

Bug: Declaring a class reference without initializing it: 

BankAccount account;
account.Deposit(100); // System.NullReferenceException: Object reference not set to an instance of an object

Fix: The stack variable holds null (address 0x00). You must allocate the instance using new BankAccount() before invoking methods or assigning fields.
